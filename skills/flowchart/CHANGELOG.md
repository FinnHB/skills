## 2026-06-07 (v0.8.0)

## 2026-06-06 (v0.7.0)
- New §7 "Deep mode": an explicit "deep" request generates the root chart plus recursive per-stage drill-downs. Design settled in a user grilling session, then hardened by a three-agent critique (skill-craftsmanship, failure-mode red team, reader-value calibration):
  - **Chartability test** decides which stages earn a sub-chart: ≥4 post-fold steps where swapping two adjacent steps breaks the process. Calibrated against the hand-built AcademicPaperWriter set (root + set-academic-env + install-workflow): steps-only reproduces that tree exactly and yields zero sub-charts on the contrast charts (refine-heavy, genankideck). The originally proposed "OR ≥1 genuine decision" prong **failed calibration** — three false positives (import public-data gate, signoff integrity gate, bootstrap already-a-repo branch), zero contribution to the true positives — so decisions only earn diamonds inside charts that qualify on steps.
  - **Caps**: 2 levels below root and ≤12 files per run (red team's worst case without it: 91 files = guaranteed mid-run death → shipped root full of dead links). Going deeper/wider = re-run deep on a sub-chart, which re-roots there. At a cap, §2.3's over-budget fix becomes merge-only and the stage is reported as a re-root candidate (third tree verdict).
  - **Binding tree statement** before generation: per-stage verdicts + every output filename; hrefs and `cp` targets copy from it, never re-derived (slugs were judgment calls — "Install writing workflow and automation" → `install-workflow` isn't mechanically derivable, so root-first link prediction needs pinned names). §2.3 reworded into a named, recursive drill-down convention; §2.2 gained the mode-switch pointer so the flat stage list doesn't fire first.
  - **Navigation with zero template changes**: breadcrumb as inline-styled link in the existing kicker slot, parent name linked in the subtitle (the kicker alone is the page's most de-emphasized text — insufficient as sole up-navigation), child title = `Stage · Parent · Process map` (prevents identical browser tabs from same-named stages under different parents). Re-rooting preserves the existing breadcrumb (read kicker href before `cp` clobbers it).
  - **Set integrity**: every chart passes §6 individually; cross-file href grep + `test -f` doubles as the resume protocol after interrupted runs; orphans reported, never deleted; deep set atomic in one directory; open the root only.
- Calibration caveat recorded: the hand-built pair predates the current template and contains no links in either direction (the middle chart's P2 even violates §2.3's link rule), so it validates the test and filenames but not the breadcrumb wiring — first real deep run is the wiring test.
- Rejected: an index page (root chart + breadcrumbs are the navigation; an index restates the root as a bullet list and drifts); approval pause before generating (§2.2's state-then-proceed precedent; "deep" was the consent); the decision prong of the chartability test (failed calibration, above); parallel subagents + stitching pass (cold starts re-read everything; deterministic filenames make sequential root-first linkable at write time with no reconciliation); depth-3 override syntax (re-rooting is strictly simpler); a template `a` style rule or dedicated breadcrumb slot (slot content absorbs both, keeping the template byte-identical).
