# /add-module <name> [--lang python|julia|r]

Scaffold a self-contained analysis module under `code/<name>/` with the canonical layout,
a language-appropriate lockfile + env, and a per-step provenance recorder (`pipeline.py`).

**Python is the default language.** Julia and R are opt-in via `--lang julia` or `--lang r`.
All three share the same `pipeline.py` — only the lockfile, env dir, and `run.sh` interpreter differ.

**On-demand only.** This skill is invoked by the user when a paper needs code.
Nothing is created at bootstrap. Theory-only repos have no `code/` at all.

## Step 0 — Parse arguments

Parse `$ARGUMENTS`:
- First non-flag token is `<name>` (required). If absent, refuse:
  > "/add-module requires a module name. Example: /add-module empirical"
- `--lang python|julia|r` sets the language (default: `python`). If an unrecognised value is
  passed, refuse:
  > "Unknown --lang value '<x>'. Supported: python, julia, r."

## Step 1 — Preconditions

Run these checks. On failure, refuse with the exact message shown and stop.

1. **Inside a paper repo.** Check that `paper_config.yaml` exists in the current directory:
   ```bash
   [ -f paper_config.yaml ] || { echo "/add-module must run inside a paper repository (no paper_config.yaml found)."; exit 1; }
   ```

2. **Module does not already exist.** If `code/<name>/` already exists, refuse:
   > "Module 'code/<name>/' already exists. Remove it first or choose a different name."

## Step 2 — Resolve the skill's own assets directory

The skill's asset files live next to this SKILL.md in `assets/`. Resolve the path at runtime:

```bash
SKILL_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" 2>/dev/null && pwd)"
# If SKILL_DIR is unavailable (Claude Code invocation), locate via the paper's .claude/skills/
SKILL_DIR="${SKILL_DIR:-$PWD/.claude/skills/add-module}"
ASSETS="$SKILL_DIR/assets"
```

## Step 3 — Scaffold the module directory tree

Create the standard layout:

```
code/<name>/
├── src/
│   └── 01_example.<ext>     starter script (language-specific extension)
├── output/                  git-ignored generated artifacts
├── data/
│   ├── raw/
│   └── README.md            data manifest stub
├── tests/
├── <lockfile>               language-specific (see Step 4)
├── pipeline.py              provenance recorder (copied from assets/)
├── run.sh                   run-all script (language-specific interpreter)
├── README.md                module description
└── .gitignore               copied from assets/module.gitignore
```

Create directories:
```bash
MODULE="<name>"
BASE="code/$MODULE"
mkdir -p "$BASE/src" "$BASE/output" "$BASE/data/raw" "$BASE/tests"
```

Copy verbatim from `$ASSETS/`:
- `pipeline.py` → `code/<name>/pipeline.py`
- `module.gitignore` → `code/<name>/.gitignore`

Write `code/<name>/data/README.md` (data manifest stub):
```markdown
# Data manifest — <name>

| file | source | url | sha256 | size |
|------|--------|-----|--------|------|
| _example.csv_ | | | | |

Large raw files are git-ignored. Add fetch instructions to `data/fetch.sh` if needed.
```

Write `code/<name>/README.md` by copying `$ASSETS/README.md` and substituting `{{MODULE}}` → `<name>`.

## Step 4 — Language-specific scaffold

### Python (default, `--lang python`)

**Lockfile:** copy `$ASSETS/requirements.txt` → `code/<name>/requirements.txt`.

**Starter script:** copy `$ASSETS/01_example.py` → `code/<name>/src/01_example.py`,
substituting `{{MODULE}}` → `<name>`.

**run.sh:** copy `$ASSETS/run.sh` → `code/<name>/run.sh` (already targets `.py`), then `chmod +x`.

**Virtual env:** Create the module's `.venv`:
```bash
cd "code/$MODULE"
if command -v uv &>/dev/null; then
    uv venv .venv --quiet 2>/dev/null || true
    uv pip install --python .venv/bin/python --quiet -r requirements.txt 2>/dev/null || true
    ENV_STATUS="created with uv"
elif command -v python3 &>/dev/null; then
    python3 -m venv .venv
    .venv/bin/pip install --quiet -r requirements.txt 2>/dev/null || true
    ENV_STATUS="created with python3 -m venv"
else
    ENV_STATUS="NOT CREATED — install uv or python3, then run: python3 -m venv .venv && pip install -r requirements.txt"
fi
```

If `uv`/`python3` are absent: scaffold files + lockfile, skip env creation, print the exact
command to run later. Never hard-fail.

### Julia (`--lang julia`)

**Lockfile:** copy `$ASSETS/Project.toml` → `code/<name>/Project.toml`.
(Manifest.toml is generated by `Pkg.instantiate()` — do NOT pre-create it.)

**Starter script:** write `code/<name>/src/01_example.jl`:
```julia
# Starter step. Replace with real analysis. Demonstrates provenance recording.
run(`python pipeline.py record --step src/01_example.jl --outputs output/example.txt`)
mkpath("output")
write("output/example.txt", "hello from <name>\n")
run(`python pipeline.py record --step src/01_example.jl --inputs "" --outputs output/example.txt`)
```

**run.sh:** write `code/<name>/run.sh` with the Julia interpreter:
```bash
#!/usr/bin/env bash
set -euo pipefail
cd "$(dirname "$0")"
for s in src/[0-9]*.jl; do [ -e "$s" ] || continue; echo "── $s ──"; julia --project=. "$s"; done
python pipeline.py check
```
Then `chmod +x code/<name>/run.sh`.

**Env:** if `julia` is available, print the instantiate command; do not run it automatically:
> "Julia env: run `julia --project=code/<name> -e 'using Pkg; Pkg.instantiate()'` to create Manifest.toml."
If `julia` is absent, print the same instruction — never hard-fail.

### R (`--lang r`)

**Lockfile:** copy `$ASSETS/renv.lock` → `code/<name>/renv.lock`.

**Starter script:** write `code/<name>/src/01_example.R`:
```r
# Starter step. Replace with real analysis. Demonstrates provenance recording.
dir.create("output", showWarnings = FALSE)
writeLines("hello from <name>", "output/example.txt")
system("python pipeline.py record --step src/01_example.R --inputs '' --outputs output/example.txt")
```

**run.sh:** write `code/<name>/run.sh` with the R interpreter:
```bash
#!/usr/bin/env bash
set -euo pipefail
cd "$(dirname "$0")"
for s in src/[0-9]*.R; do [ -e "$s" ] || continue; echo "── $s ──"; Rscript "$s"; done
python pipeline.py check
```
Then `chmod +x code/<name>/run.sh`.

**Env:** if `Rscript` is available, print the renv init command; do not run it automatically:
> "R env: run `Rscript -e 'renv::init()'` inside code/<name>/ to initialise the renv library."
If `Rscript` is absent, print the same instruction — never hard-fail.

## Step 5 — Write .gitignore

The `.gitignore` was already copied from `$ASSETS/module.gitignore` in Step 3. Verify it exists:
```bash
[ -f "code/$MODULE/.gitignore" ] || cp "$ASSETS/module.gitignore" "code/$MODULE/.gitignore"
```

## Step 6 — Report

After scaffolding, print a clear summary:

```
Module scaffolded: code/<name>/

Tree:
  code/<name>/
  ├── src/01_example.<ext>
  ├── output/             (git-ignored)
  ├── data/raw/
  ├── data/README.md
  ├── tests/
  ├── <lockfile>
  ├── pipeline.py
  ├── run.sh
  ├── README.md
  └── .gitignore

Env status: <ENV_STATUS>

To run:
  bash code/<name>/run.sh

To check provenance later:
  python code/<name>/pipeline.py check

\graphicspath reminder (add to paper/main.tex manually if using generated figures):
  \graphicspath{{../code/<name>/output/}}
```

**Do NOT edit `paper/main.tex` automatically.** The graphicspath line is a printed reminder only.

## Non-goals

- Do not create any modules at bootstrap or as a side-effect of this skill being installed.
- Do not edit `paper/main.tex` or any manuscript file.
- Do not run `install.sh` or refresh global `~/.claude/skills`.
- Do not add Snakemake, DVC, or any other pipeline orchestrator.
- Do not pre-create `Manifest.toml` (Julia) or `renv/library/` (R) — those are generated by the
  respective toolchains.
